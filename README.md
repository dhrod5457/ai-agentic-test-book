# AI Agent Test Engineering Book

AI Agent가 코드를 생성·수정할 때 함께 만들어야 하는 테스트의 원칙, 품질 기준, 검증 방법을 정리하는 책의 연구 저장소입니다.

현재 단계는 **자료 조사와 원문 확인**입니다. 책 본문 집필보다 먼저 논문, 오픈소스, 벤치마크, 테스트 도구와 실제 테스트 안티패턴을 수집하고 근거를 정리합니다.

집필·검수 기준은 `dhrod5457/published-book`의 `BOOK-WRITING-MANUAL.md`를 따릅니다.

## 현재 연구 질문

1. AI Agent가 코드를 변경할 때 어떤 종류의 테스트를 반드시 추가하거나 수정해야 하는가?
2. Agent가 만든 테스트가 단순히 통과하는 것이 아니라 실제 결함을 잡는다는 것을 어떻게 검증할 것인가?
3. 단위·통합·계약·E2E·속성 기반·변이·퍼징 테스트를 어떤 조건에서 선택할 것인가?
4. 테스트 생성 Agent가 코드 커버리지만 높이는 방향으로 보상 해킹하는 것을 어떻게 막을 것인가?
5. 구현을 테스트에 맞추거나 테스트를 구현에 맞춰 억지로 성공시키는 행동을 어떻게 탐지할 것인가?
6. `Thread.sleep`, 고정 지연, 무분별한 재시도처럼 flaky test를 숨기는 패턴을 어떻게 금지할 것인가?
7. 과도한 mock, 의미 없는 assertion, 자기 구현을 그대로 복제한 expected value 같은 '쓰레기 테스트'를 어떻게 판별할 것인가?
8. Agent가 만든 테스트를 독립적인 품질 게이트로 검증하려면 어떤 자동화가 필요한가?

## 현재 원칙

테스트 성공 여부 하나만으로 품질을 판단하지 않습니다.

다음 흐름을 기본 연구 가설로 둡니다.

```text
코드 변경
  -> 테스트 생성/수정
  -> 테스트 실행
  -> 독립 품질 검증
     - assertion 유효성
     - mutation score
     - 경계/실패 조건
     - flaky 여부
     - 외부 의존성 통제
     - 회귀 재현성
  -> 회귀 테스트로 고정
```

특히 다음 행위는 별도 안티패턴으로 조사합니다.

- assertion을 삭제하거나 약화해 테스트를 통과시킴
- expected value를 현재 구현 결과로 그대로 복사함
- 예외를 삼키고 성공 처리함
- 테스트 자체를 disable/skip 함
- mock이 자기 기대값을 그대로 반환하도록 구성함
- 실제 검증 없이 `assertTrue(true)` 같은 형식적 assertion을 추가함
- 실패 테스트에 `Thread.sleep`을 추가해 타이밍 문제를 숨김
- flaky test를 원인 제거 없이 재시도로 감춤
- 테스트 커버리지를 높이기 위해 의미 없는 경로만 호출함
- 프로덕션 코드를 테스트 편의에 맞춰 왜곡함
